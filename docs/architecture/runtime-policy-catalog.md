# Runtime policy catalog

Status: under review. M6 rows contributed here; other owners' rows pending. Shared document —
M5 coordination pending. Date: 2026-10-12.

What the system does when each degraded or failure path is triggered. Each failure mode has a
defined response and operational fallback.

| Failure mode | Detection | Response | Fallback (concrete) | Owner |
| --- | --- | --- | --- | --- |
| Storage write unavailable (`append`/`commit`) | Backend throws on `commit`; store returns `failed` (`storage_unavailable`) | Do not acknowledge persistence | Mark evidence incomplete; block new turns pending recovery; **Stop and local cancellation never wait for the write** | M6 |
| Duplicate event / delivery | Existing identity and accepted content match, including delivery classification/index/persona attribution | Return `duplicate`; do not duplicate state | Keep first record; no replay of output | M6 |
| Conflicting content (same id, changed text or attribution) | `textHash`/content, `segmentIndex`, `personaProfileId` or `personaProfileVersion` mismatch | Return `conflict`; never overwrite | Preserve recorded fact; record the conflict | M6 |
| Inconsistent delivery record | `classification`/`terminalOutcome` pair invalid, malformed supporting event (omitted `versions` or a null/non-string version member), or known delivery↔event provenance / `sessionId`/`turnId`/`segmentId`/`outputId` mismatch | Reject as one paired `failed` (`invalid_delivery` / `invalid_event` / `inconsistent_delivery`); persist nothing | Keep the prior record; a corrected retry reusing the identity and sequence applies; unknown event provenance stays absent, never inferred | M6 / M5 |
| Unsupported event payload (not a JSON value) | Payload validated before publication | Reject with `unsupported_payload`; persist nothing | Keep the prior record unchanged; the producer must send a JSON value | M6 |
| Interrupted atomic commit | Backend failure mid-commit | `commit` is atomic — no partial state | Resume from last committed state; unresolved outputs stay `unknown` | M6 |
| Projection gap | `event.seq > appliedSeq + 1` | Do not advance `appliedSeq` | Projection must not claim current history until it catches up | M6 |
| Restart with unresolved output | Startup reconciliation | Begin stopped; restore only confirmed history | Unresolved outputs remain `unknown`; no automatic replay | M6 / M5 |
| Migration failure (unsupported schema version, or apply error) | `migrate` rejects or rolls back | Refuse to open the database; keep the prior version | Restore from the pre-migration backup under `<dbDir>/backups/` | M6 |
| Startup recovery (restart) | `recovery-view` reads committed deliveries | Restore only confirmed history; keep unresolved `unknown` | No replay; an unresolved segment is never quoted as spoken | M6 / M5 |
| Standalone corpus-runner selection failure | `runSelectionCase` catches a `SelectionCallError` (including abort, deadline and invalid-deadline codes), a generic throw, or empty candidates/intents | Record one per-case `technical-failure` with `adoptedScore: null`, reason and diagnostic; continue remaining corpus cases | No fallback and no semantic score; the failed case remains visible | M3 |
| Runtime selection timeout, cancellation, expired authority or superseded snapshot | M5 coordinator observes timeout/abort, expired authority/deadline, or a superseded snapshot | Mark the turn `stale`; produce no plan/output | No fallback into output; late results remain stale | M3 / M5 |
| Fresh runtime selection rejection or invalid proposal | M5 coordinator observes a thrown selection call or a resolved schema-invalid/mis-correlated/unoffered/disallowed-intent proposal while authority is fresh | A thrown call is recorded `failed`; a resolved but unaccepted proposal is recorded `invalid`; neither proposal is accepted | Use the authorised `m5-fallback` when eligible and allowed; otherwise defer; never bypass Stop or expiry | M3 / M5 |
| Runtime reaction cancellation or revocation | M5 coordinator observes an aborted reaction call (Stop or superseded epoch) | Record the provider attempt as `aborted`; revoke the segment before output dispatch | Abort the segment (`revoked`); speech does not continue for the revoked turn | M3 / M5 |
| Runtime reaction timeout, rejection, invalid decision or stale capability | M5 coordinator observes timeout (`timeout`), ordinary rejection (`failed` — M5 does not inspect `ReactionCallError.code`), schema-invalid/mis-correlated result (`invalid`), or a correlated result with stale capability revision (`accepted` with `no-op`) | Record the corresponding provider disposition; do not dispatch an unadvertised or stale-capability avatar action | Fall back to `no-op` for the segment while otherwise-valid speech continues | M3 / M5 |
| Working-memory admission refusal | `WorkingMemoryStore.record` sees a delivery naming a session the store is not bound to (or a note naming one), an acknowledgement that is not `applied` (including `duplicate`, `conflict` and `failed`), an `applied` acknowledgement whose effective classification is not `fully-delivered`, empty/whitespace-only note text, a note containing a line break, non-finite or non-positive expiry inputs (`nowMs` / `ttlMs`), or a producing `ConfirmedDelivery` that does not classify into the spoken bucket (`classifyMemoryBucket`: for example a fully-delivered audio delivery with no receipt, a partial record, or an audit-only record) | Return `refused` with `session-mismatch` / `commit-not-applied` / `commit-not-spoken` / `empty-text` / `text-not-single-line` / `invalid-expiry` / `not-spoken-bucket`; the store is unchanged and the item never becomes pending | The item is not remembered in working memory; a re-applied delivery or a corrected single-line note may be admitted later, but a delivery that does not classify into the spoken bucket is refused until its evidence makes it spoken, and a read for another session throws rather than returning an empty block | M4 |
| Context block dropped for size or for a non-finite dimension | The rendered state or working-memory block exceeds its section cap (`state` / `workingMemory` under a plan, `maxCharacters` without one) or the state and working-memory blocks together exceed `maxCharacters`; or `renderStateBlock` returns null because a dimension is not finite | Drop the block whole (`null`) and record one budget warning naming the block; a state block with a non-finite dimension is dropped with its own distinct validation warning and is not counted as a budget drop (`used` and `dropped` stay 0) | Context assembles without that block; history and recall are unchanged for a dropped working-memory block, and the remaining budget is spent on the other sections in the persona → state → workingMemory order | M4 |
| State-plus-plan combination (former refusal retired) | `assembleDialogueContext` receives `state` together with a `budgetPlan`; the earlier implementation threw for that combination instead of assembling it | Do not refuse: keep the block only when it fits the plan's `state` section, charge the kept block to `state.used`, and still subtract it from the shared pool so history cannot exceed `maxCharacters` | A block longer than its section cap is dropped whole with the budget warning; the state block keeps precedence and the working-memory block yields first, and the plan's history floor is unchanged | M4 |
| Contract-violating listener-history source | A `ListenerHistoryPort` returns the selected input's own event, or returns turns out of `(receivedAtMs, eventId)` order | Filter out the selected input's event without recording an exclusion, then stably re-sort by `(receivedAtMs, eventId)` before any cap or budget decision | The assembly is identical to a conforming source with the same turns: the cap keeps and the budget drops the same rows, and the exclusion order does not change | M4 |

Decision rows are recorded above; synthesis failure and renderer disconnect remain owned by M1/M5
and pending their entries here.

## Pipeline gates (M6)

These rows are decisions about the CI pipeline, not the deployed service. Isla has no deployed runtime
yet, so the actor is the pull-request author and the M6 reviewer reading the required check; there is no
pager and no on-call. A row is `enforced` only when the named test proves it; `convention` means the job
itself fails but no dedicated record is written. A failure record is written under
`.cache/gate-failures/` and uploaded by CI.

| Policy | Trigger | Action | Decision | Evidence | Escalation | Test | Owner |
| --- | --- | --- | --- | --- | --- | --- | --- |
| POL-PIPE-01 | a gate step did not run, was skipped or was cancelled | report every gate that did not run as not-verified, never as pass; record the outcome map | fail-closed | `gate_outcomes` | none; the summary names the skipped gates | `gate-record.test.ts::records a gate that did not run` | M6 |
| POL-PIPE-02 | `verify` is red on a push to `main` | record the red push run on main; a human reverts or fixes forward within one working day | fail-closed | `run`, `failed_gates` | the red run on `main` is the signal | convention (post-merge run) | M6 |
| POL-G1-01 | changed code path not covered by any approval record, or a named test is missing | block the merge; never create, edit or backdate an approval record | fail-closed | `files`, `approval_id`, `record_commit`, `first_code_commit`, `approved_at` | none; the red check notifies the author | `test-approval-gate.test.ts::fails when an approval does not cover a changed code file` | M6 |
| POL-G1-02 | record commit is not an ancestor of the first code commit, or the approval is dated later | block the merge; reorder the commits rather than rewriting history to fake the order | fail-closed | `approval_id`, `approved_at`, `first_code_commit` | none | `test-approval-gate.test.ts::fails when the record was committed after implementation began` | M6 |
| POL-G1-03 | history or object database unavailable | block the merge; unknown history is not approval, so fetch the history and re-run | fail-closed | `reason` | none | `test-approval-gate.test.ts::fails closed when the history answer is unavailable` | M6 |
| POL-G4-01 | measured claim without an evaluation table, or the table omits a fixed condition | block the merge; mark the number unverified and never substitute zero or a guess | fail-closed | `document`, `line`, `claim`, `missing` | none; the document owner acts | `eval-gate.test.ts::fails a measured claim when no evaluation table exists` | M6 |
| POL-G4-02 | claim row without a value or conditions | block the merge until the claim row carries a value and its fixed conditions | fail-closed | `claim`, `missing` | none | `eval-gate.test.ts::fails a claim row with no value` | M6 |
| POL-G4-03 | no table and no claim | pass the step, record not-run, and refuse any numeric claim until a table exists | three-state | `reason` | none | `eval-gate.test.ts::is not run when there is no table and no claim` | M6 |
| POL-G4-04 | a claim exemption passed its expiry | block the merge; an expired exemption is debt that must be re-reviewed, not renewed silently | fail-closed | `document`, `line`, `expires` | none | `eval-gate.test.ts::fails the same line after the exemption expires` | M6 |
| POL-G6-01 | code or prompt changed without a log update | block the merge; never append an entry on the author's behalf | fail-closed | `changed_files`, `log_changed` | none | `ai-use-log-gate.test.ts::requires the log when a code file changes` | M6 |
| POL-G6-02 | a new entry cites a commit not reachable from HEAD, or any cited case/invariant does not exist | block the merge; the entry owner corrects the reference, the gate never rewrites it | fail-closed | `entry`, `field`, `value` | none; entry owner named | `ai-use-log-gate.test.ts::rejects a new entry whose commit is not reachable from HEAD` | M6 |
| POL-G6-03 | a register, the object database, a commit history or a log copy is unreadable or unclassifiable: `object-database`, `commit-history`, `case-registry`, `invariant-register`, `base-log` or `head-log` evidence from a missing or unreadable file, unparsable YAML, a document whose `entries` is not a list, or a recursive alias in the base or head log | block the merge; an unreadable register or log copy is a failure, never an empty register or an unclassified entry | fail-closed | `register` | none | `ai-use-log-gate.test.ts::fails closed when the object database is unavailable`; `ai-use-log-gate.test.ts::fails closed when the base log is not valid YAML`; `ai-use-log-gate.test.ts::fails closed when the base cannot be read as an entries list`; `ai-use-log-gate.test.ts::fails closed on a recursive alias in the base log`; `ai-use-log-gate.test.ts::fails closed on a recursive alias in the head log` | M6 |
| POL-G6-04 | a baseline exemption expired | block the merge; the exemption expired and must be re-reviewed or removed | fail-closed | `value`, `expires` | none | `ai-use-log-gate.test.ts::rejects a baselined missing commit after its expiry` | M6 |
| POL-TR-01 | missing component, unknown case, missing test file or unknown test title | block the merge; the row owner repairs the code, test or citation the row names | fail-closed | `row_key`, `code`, `detail` | none | `trace-fitness.test.ts::rejects a citation whose title the file does not contain` | M6 |
| POL-TR-02 | ADR cell names no number and has no unexpired exemption | block the merge; name an allocated ADR or record an explicit em dash | fail-closed | `row_key`, `cell` | none | `trace-fitness.test.ts::rejects an ADR cell that names no ADR number` | M6 |
| POL-TR-03 | citation without a `test/` path, or a row outside any parsed table | block the merge; a row the parser cannot see is not evidence, so fix the table shape | fail-closed | `code`, `detail` | none | `trace-fitness.test.ts::rejects a citation that names a test file without a path` | M6 |
| POL-TR-04 | test cited without an exact title | pass with an advisory count; the citation stays unverified until migrated to file::title | fail-open-with-debt | `detail` | none | `trace-fitness.test.ts::reports a prose-only citation as advice, not a failure` | M6 |
| POL-G2-01 | typecheck or lint failure | block the merge; no auto-fix and no suppression of the diagnostic | fail-closed | `step`, `outcome` | none | convention (job fails) | M6 |
| POL-G3-01 | requirements registry or boundary failure | block the merge; never regenerate the registry to make the schema pass | fail-closed | `step`, `outcome` | none | convention (job fails) | M6 |
| POL-G5-01 | any prior test fails | block the merge; never skip, delete or weaken a failing test | fail-closed | `step`, `outcome` | none | convention (job fails) | M6 |
