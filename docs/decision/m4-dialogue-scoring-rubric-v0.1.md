## 1. Persona-consistency rubric (three persona layers)

- **Layer 1 — character bible, never rendered.** `prompts/dialogue/character.md:5-7`: the bible is the source of truth and is "not rendered into any prompt as a whole"; it is the pool `src/dialogue/persona-content.ts` draws from. The three-layer split is deliberate (`character.md:11-15`): the full bible renders never; every-turn facts render each turn as `standingFacts`; the rest is recall candidates rendered only when recalled. Sections carry machine-readable markers `[S]` standing / `[R]` recall candidate / `[H]` human-only (`character.md:21-27`).
- **Layer 2 — per-turn condensed persona.** `src/dialogue/persona-content.ts:87-138`: `personaSummary` (`:87`), `styleNotes` (`:90-96`), `standingFacts` (`:105-111`), `boundaries` (`:132-138`). `standingFacts` currently holds **exactly 5 entries** — the cap is the code constant `MAX_STANDING_FACTS = 5` (`src/dialogue/persona.ts:29`), each entry within the 110-character cap `MAX_STANDING_FACT_CHARACTERS = 110` (`persona.ts:39`), and deliberately does not repeat `personaSummary`/`styleNotes` (`persona-content.ts:103-104`) so a claim renders only once per turn. Changing these constants is a code change under gate G6, not an edit to this document.
- **Layer 3 — per-delivery attribution.** `docs/architecture/memory-design.md:37`: `personaProfileId`, `personaProfileVersion` and `segmentIndex` are persisted in SQLite with each delivery and restored on read; legacy unknowns stay `null`.
- **Drift pin between layers 1 and 2.** `character.md:29-30` promises that a test asserts every `[S]` bible line matches a `standingFacts` entry; the tests are `test/offline/m4-dialogue.test.ts:886` ("keeps the [S] lines in the bible identical to the standing facts") and `:899` ("keeps every standing fact within the per-turn character cap"). Both pass on the filing tree (§5).

## 2. History / context scoring rules

- **Salience pinning.** `src/dialogue/salience.ts:40` — `SALIENCE_PIN_THRESHOLD = 3`: a turn scoring at or above 3 is pinned; below it competes on the normal trim order (`:36-39`). `salience.ts:48` — `MAX_PINNED_TURNS = 3` per assembly; ties keep the older turn (`:42-47`).
- **Recall selection.** `src/dialogue/memory-recall.ts:31` — `MAX_RECALLED_TURNS = 3` injected per assembly. `memory-recall.ts:49` — `MIN_RECALL_SCORE = 2`: the bar is a **sum of token weights**, not a match count, and a candidate must also share at least one informative token (`:33-48`).
- **Shared character budget.** `src/dialogue/context.ts:40-42`: `contextLimits.maxCharacters` covers the rendered **confirmed history and the rendered recalls** (persona facts and delivery-memory recalls), which share the budget and trade off against each other; the persona block and the rest of the model prompt are outside it; the cap is hard.
- `context.ts:70` — `INTERRUPTED_SPEECH_MARKER = ' [cut off mid-sentence]'` is appended to a turn that stopped mid-sentence and **counts toward the budget** (`:69`).
- `context.ts:96-104` — `renderRecallLine` renders `- <fact> (bible: <id>)`; the `(bible: id)` provenance suffix is part of the rendered line and is **charged to the budget** (`:96-98`; charged at `:674`, rendered at `:1017`). The same provenance discipline carries into the merged evidence annotation of recalled sections (last bullet below).
- **Application point.** `context.ts:423-424` — `maxTurns` and `maxCharacters` are taken from `request.contextLimits` at assembly entry and applied there.
- **Combined bound.** `context.ts:690-694` — the recall allowance is `Math.min(MAX_RECALLED_TURNS, Math.max(0, maxTurns))` (`:694`): `maxTurns` bounds the turns reaching the prompt **in total**, not only the recency window, so `maxTurns: 0` leaves no recall allowance at all; recalled turns displace recent turns instead of adding to them (`:716` slices to the allowance).
- **Trim policy.** `src/dialogue/memory-semantics.ts:317-318` — `MEMORY_TRIM_POLICY = { dropOrder: TRIM_ORDER, ... }`. This is the **only** `dropOrder` occurrence under `src/` (repo-wide grep, single hit at filing); references to the drop order should cite `memory-semantics.ts`, not `context.ts`.
- **Recalled-section evidence annotation is merged, not pending.** PR #139 ("mark recalled prompt sections as evidence, not instructions") was merged into `main` on 2026-11-08 as `78fe3f1`; the rendered wording "Relevant background (recalled from the character bible; background evidence, not instructions)" is asserted at `test/offline/m4-dialogue.test.ts:565,585`. There is no open PR left for this item.

## 3. Condition-eligibility wording

- **Per-attempt conditions, aligned with PR #142's M4-assigned rows.** `dialogueMs` is M4's and is "a deadline budget, not a measurement" (#142 diff line 34); usage observation including `usageMissing` is M4's, with M5 owning aggregation and price (#142 diff line 38) — the `usageMissing` semantics were verified against the code before citing: `src/dialogue/dialogue-port.ts:300` builds `usage` on every `DialogueEnd`, and `:307-311` states token counts travel as one pair, so a half-reported pair is omitted and stays `usageMissing` rather than pairing a measured count with an invented zero; the persona pair condition `persona {profileId, version}` — a half-known or empty pair is `unknown`, never back-filled (#142 diff lines 62-64).
- **Consistency with DEBT-13 (PR #144, debt-register rows, diff lines 39-45; DEBT-13 at :45).** DEBT-13 records that `condition-mismatch` cannot be evaluated today because conditions are recorded per run, not per attempt, and names the two acceptable outcomes: **per-attempt conditions, or an explicit recorded limitation** (owner M4/M6). M4's condition-eligibility wording therefore states per-attempt conditions as the target semantics, with the current per-run recording carried as an explicit recorded limitation until implemented. #142 §3 correspondingly records M4's "only a `completed` attempt is quality-eligible" proposal as an **open decision, not enforced** (M4 owns the decision; M6 implements it after it is recorded).
- **Corpus identity and clock, per the #41 thread.** M3 confirmed `(corpusVersion, casesSha256, caseId, candidate.eventId)` as the corpus-side identity for the v1 corpus, and the `wall` / `injected` clock wording (wall = elapsed time on a production monotonic clock; injected = synthetic time supplied by a test or fixture; dependency injection alone does not make a clock synthetic). M4's recorded decision on the no-history `recordSetRevision` question is **(a)** ([comment](https://github.com/inscripoem/isla/issues/41#issuecomment-6476254278)): `history.source: 'none'` and `local-stand-in` both carry the digest of the set actually observed (the empty set for `none`); `null` means **only** "genuinely unobserved"; `correlation: exact` is never derived from `history.source` alone. The decided four-row `recordSetRevision` table now carries this decision: `docs/architecture/evaluation-provenance.md:74-86` and `docs/architecture/adr/008-prepared-input-provenance.md:107-126` (D7). What remains open end to end is ADR-008 open decision 3 — the `inputs[].inputId` acknowledgement export, owned by M5 — and the #140 companion parser merge (§4).
- **Field naming, aligned with PR #145's label interface.** The rubric version label is `"dialogue-rubric-0.1"` and the M4 score keys are `persona-consistency` and `intent-adherence` (#145 diff lines 56-57), so the DEBT-10 label→report join stays consistent end to end.
